# v0.3.3 拖拽排序

## 使用与交互

重启 DSH 加载当前源码后使用：

- 左侧任务列表：在“－”、优先级、最近更新、添加日期任意模式下拖住原有拖拽柄。源任务淡化，目标前/后显示金色插入线及落点名称；松开后保存。
- 拖后仍符合排序规则时保留当前模式；打乱规则（如 P2 放到 P1 前）则切换为“－”。同优先级、同日期内可自由调整，顺序以保存后的序号为准。失败或取消不切换模式。归档列表不接受拖动。
- 详情目标：直接拖标题行，将整个目标及其子项放到另一目标前/后，不新增拖拽柄。
- 详情进展：直接拖标题行，在同一目标内排序；拖到另一目标的进展前/后，或拖至目标标题/动态出现的“移到目标末尾”区域，可更换所属目标。空目标也可接收。
- 拖动进展经过折叠目标时自动展开；靠近列表/详情滚动区域上下边缘时滚动。
- 拖拽只排序/调整进展所属目标，不自动升降级。目标不跨 Quest 移动，进展只在当前 Quest 内移动。
- Esc 或在无效位置松开取消，不保存；拖到自身不改变顺序。
- 正在保存、归档、DSH 模拟预览、弹出输入表单期间禁止启动拖动。空白新增行不再阻止其他条目启动拖动；输入框、按钮、链接不触发条目拖动；双击标题仍可编辑。按住 Alt 可选择标题文字。开始条目拖动时清除残留选区，避免全局选区拦截拖动。
- 本交互面向桌面鼠标/触控板，未声称支持手机触屏拖放。

## 保存与一致性

通过 `/quest-journal/ops` 提交单条 `reorder_node`，包含节点、父节点、锚点和 before/after/end；Quest 同时提交 sort_mode。服务端在事务内读取最新同级列表、验证范围、移动并重新编号，不接受前端完整排序数组覆盖。

Quest 使用当前排序模式的完整活动列表作为基础，包括被筛选隐藏的任务。拖后检查优先级/日期是否仍单调，返回有效 sort_mode。由自动排序切到“－”时，未拖条目保持刚才看到的相对顺序。Quest 纯排序保留 created_at/updated_at，避免“最近更新”因拖动本身变动导致二次跳位；仍记录排序 Trace。

跨目标移动进展保留 id、完成/阻塞、附件与 Trace，更新新旧目标时间。目标移动保留子树。仅真实移动记录 reordered 事件；重复相同位置不产生重复历史；非法目标与批量失败回滚。新增节点使用已有最大序号加一，避免删除后序号空洞导致新条目插到中间。

自然语言指令生成期间如发生排序，原有预览的冲突检测继续生效。

## 原生浏览器回归

执行 `python3 scripts/test-browser-drag.py`，使用本机 DSH 自带 React/ReactDOM 与隔离模拟数据，在独立 Chrome 中以真实鼠标事件启动 HTML5 原生拖拽。不使用真实 DSH profile 或数据库，不下载第三方包。可用 QJ_DSH_APP、QJ_CHROME、DSH_NODE 指定程序位置。

六个场景全部通过，浏览器无运行时错误：

1. 目标标题直接拖动。
2. 空白新增行失焦时仍可拖动。
3. 优先级模式 P2 放到 P1 前切换为“－”。
4. 同优先级条目互换保留优先级模式。
5. 打乱更新时间排序切换为“－”。
6. 打乱添加日期排序切换为“－”。

未中断用户正在运行的 DSH；实际 DSH 中可重启后复核。
