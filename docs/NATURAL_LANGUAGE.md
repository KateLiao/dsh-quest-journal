# 任务内自然语言编排（v0.3）

## 用户目标与界面

在已选中的 Quest 详情中，用自然语言说明进展和下一步，让 DSH 把描述整理成可执行的目标/步骤，或更新已有节点。使用已确认的精简双栏大纲设计：标题与状态优先；行内仅保留完成、展开、悬停新增、更多菜单；日期与附件按需展开。

任务顶部提供“告诉 DSH 最新进展或下一步…”多行指令框，明确绑定当前 Quest。Enter 换行，Ctrl/⌘+Enter 提交；提交按钮为“生成变更”。生成中禁重复发送，可取消；失败保留输入并可重试。

DSH 使用当前默认模型，通过已有 llm 服务调用，复用 DSH 认证和模型配置，不另设 API Key、不调用终端、不启动可执行其他工具的 Agent。没有可用服务时明确提示，绝不以关键字规则冒充模型。

先在“目标与进展”中模拟应用后的完整大纲，再点击“应用变更”原子落库。服务端从已校验的回滚事务返回原始/投影树，客户端不自行推断操作结果。新增（金色）、修改（蓝色）、移动（紫色）有边框及文字标签；删除项保留原位对照，标“将删除”。忽略纯更新时间变化，避免所有祖先节点都被高亮。变动内容不被折叠/隐藏已完成遮挡，预览期间禁止手动编辑；取消、澄清、切换任务或冲突时恢复真实大纲。用户可取消、补充描述重新生成。模型发问时展示澄清问题，用户输入回复后连同前文继续生成。所有操作限定当前 Quest，跨任务需求提示到对应任务操作。

## 主要验收案例

当前任务“配合跟进 示例项目 A 的不稳定测试情况”，输入：

> 现在我在优化 PRD，下一步计划和 协作者 同步思路、找研发算法确认指标、调研了解仿真平台。

预览应创建未完成目标“完成 PRD”，并挂载三个未完成子项：

1. 和 协作者 同步思路
2. 找研发算法确认指标
3. 调研了解仿真平台

“完成 PRD”是目标标题，不能因此把 status 设为 completed；当前进展“正在优化 PRD”保留在目标描述。若已存在明确匹配的 PRD 目标，则优先复用，避免重复创建。提到 协作者 不代表发送消息或预约会议。

## 支持的表达

| 意图 | 示例 | 处理 |
|---|---|---|
| 规划与拆解 | 接下来完成 PRD，先同步再确认指标 | 创建或复用目标，按表达顺序添加 Step；不虚构任务 |
| 新增步骤 | 给“完成 PRD”加一步调研仿真平台 | 精确定位目标、追加 Step |
| 更新进展 | PRD 已改到第二版，仍在评审 | 添加文本备注，保持未完成 |
| 完成/重新打开 | 与 协作者 同步已完成；指标确认重新打开 | 仅更新明确指定节点，不自动级联父子状态 |
| 阻塞/解除 | 指标确认卡在算法数据；资料到了解除阻塞 | 更新独立阻塞状态和原因，不推定完成 |
| 优先级 | PRD 提升为 P0 | 更新结构化优先级 |
| 标题与描述 | 把目标改名为… | 修改指定节点，不覆盖无关描述 |
| 链接 | 给 PRD 挂上 https://… | 添加用户给出的真实链接 |
| 删除与层级调整 | 删除这个重复步骤；把这条升为目标 | 预览明确展示删除/移动；沿用三层结构限制 |
| 多意图 | 同步已完成，指标阻塞，补充平台调研 | 生成同批操作，整批成功或整批回滚 |
| 歧义 | 把“测试”完成（存在两个同名节点） | 返回候选与问题，不任意选择 |
| 无任务变更 | 你好；帮我联系 协作者 | 说明可处理的范围，不伪造任务操作或对外消息 |

## 一致性与边界

- 模型只产出 JSON 计划，不能直接写库；服务端校验 op、字段、节点所属 Quest、临时引用和业务规则。
- 同批新增目标使用临时引用，子步骤能引用该目标；不存在或重复引用导致整批失败。
- 预览时以回滚事务执行校验，实际确认时再次校验；任务自预览以来变化则返回冲突，要求重新生成。
- 指令请求 ID 与确认 ID 提供幂等保护；重复点击/网络重试不能重复创建任务。预览持久化，确认结果跨重启可重放；未应用预览 30 分钟过期。
- 每个真实变更记为 source=agent；另记录自然语言指令与模型路由作为命令事件，支持追溯。失败/澄清/未确认不产生任务变更 Trace。
- 输入、上下文、输出、操作数与调用时间均设上限。超时、取消、模型失败、截断输出、无效 JSON 均不落库。
- 当前任务切换后，旧请求和预览不得在新任务中应用；归档任务只读。
- 不推断截止日期、不联系他人、不自动完成父任务；原始“进行中”只表达未完成，暂不增加新的执行状态枚举。

## 验证范围

自动验证涵盖真实领域服务、SQLite、HTTP 传输、模型服务协议替身和客户端交互链路。真实 DSH 默认模型的语义质量及实际桌面布局需重启加载后验收，离线替身测试不能证明模型一定产生理想拆解。

## v0.4 新建入口

“新建任务”新增独立的 DSH 生成方式：任务意图 → 拟定名称 → 目标与进展拆解 → 完整大纲预览 → 确认后原子创建。该模式使用创建专用模型提示与任务树 schema，不放宽当前任务内指令框的作用域。详细交互、边界与验证见 [新建任务与自动拆解](NEW_TASK_GENERATION.md)。
