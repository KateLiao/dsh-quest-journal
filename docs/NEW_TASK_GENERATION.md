# v0.4 新建任务与自动拆解

## 使用

完全退出并重开 DSH 后，点击左侧“＋ 新建任务”：

1. 默认进入“用 DSH 生成”，描述想完成的事情、背景与已知下一步。
2. 点击“生成任务与拆解”，或 Ctrl/⌘+Enter。
3. 在同一弹窗中查看完整 Quest → Objective → Step 预览。DSH 会拟定任务名称，按目标组织可执行步骤；有疑问时先提问，直接补充回答。
4. 若需要调整，在输入框补充要求再次生成；取消预览可以恢复原描述。关闭弹窗不创建任务。
5. 点击“创建任务及拆解”，整批创建并自动打开新任务。创建后清除列表搜索/筛选，回到进行中，确保新任务可见。

也可切到“手动新建”，只填名称和可选描述，不调用模型。

示例：

> 完成 示例项目 A 测试方案的 PRD，先和 协作者 同步思路，再找研发算法确认指标，最后调研了解仿真平台。优先级 P0。

应预览一个 P0 任务，下面有“完成 PRD”目标，以及三个对应进展。目标标题中的“完成”不代表已经做完，所有节点创建时均未完成。若只描述最终成果，DSH 可以建议合理、精简的行动拆解；不能虚构已经完成的事实、人员、期限或链接。

## 实现边界

- 复用 DSH 默认模型，无额外 API Key。模型只返回受限的任务树数据，不能调用工具或执行外部动作。
- 新建计划与已有任务更新分开：`/command/new/preview` 与 `/command/new/apply`。新建接口不接受已有节点 ID、任意操作或完成状态，不能修改已有任务。
- 新计划使用独立存储作用域，不依赖当前选中的 Quest；编辑已有任务的接口也不能确认新建计划。
- 服务端把任务树转换为创建操作和临时引用，回滚事务生成权威预览；确认时在事务内重新创建整棵树，任何一步失败都回滚。
- DSH 创建来源为 agent，保留原始描述、澄清上下文和模型路由的 Trace；手动新建来源为 manual。
- 请求和确认都有幂等保护，重复确认及重启后重试不会重复创建。未确认预览 30 分钟过期。
- 支持失败重试、生成中取消、关闭后忽略旧响应；确认保存中禁止关闭/切换方式。新建不会继承旧任务的预览或筛选条件。
- 任务/目标/步骤支持模型给出的 P0/P1/P2，默认 P1。至少一个目标，每个目标至少一个步骤；至多 50 项创建/优先级操作，避免一次生成过大的任务树。

## 验证

`bash scripts/run-tests.sh`：核心 20、预览兼容 25、路由 36、既有指令 15、拖拽持久化 10、新建生成 8，共 114 项检查通过；客户端事件链路与插件入口集成场景通过。

新建测试覆盖整树预览零写入、优先级、全未完成、同批引用、并发去重、重复确认、跨重启幂等、失败回滚、过期、澄清、取消，以及拒绝状态字段、已有 ID 和任意操作。客户端另覆盖 DSH/手动新建、输入保留、预览层级、确认和清除筛选后自动打开任务。

`python3 scripts/test-browser-drag.py`：保留原六个原生拖拽场景，并增加新建输入和层级预览、确认后打开新任务，共八个真实浏览器交互场景通过；使用 DSH 自带 React 与隔离模拟数据，未操作真实任务。已检查新建预览弹窗截图。

模型输出使用协议替身。真实 DSH 默认模型的自动拆解质量仍需重启加载后实际验收；没有中断正在运行的 DSH。
